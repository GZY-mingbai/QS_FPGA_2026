# FPGA TF卡 BMP 图片批量转换工具

这个脚本（`convert_images_to_bmp.py`）专为本 FPGA 工程设计，主要用于将用户手中的各种常见图片格式快速转换为满足本系统 TF 卡读取要求的标准格式：**640x480 分辨率、24 位、无压缩的 BMP 图片**。

## 1. 支持的输入图片格式

脚本内部依赖 Python 的 `Pillow` (PIL) 库进行图像解析，因此它支持绝大多数主流图像格式的读取，包括但不限于：
- `.jpg` / `.jpeg`
- `.png`
- `.bmp` (对现有 BMP 调整大小或重设色深)
- `.webp`
- `.gif` (提取第一帧)

*注：无论输入图片本身是否带有透明通道（Alpha），转换时均会统一转换为纯 RGB（24 位）模式并去除透明通道信息，以防止 FPGA 端读取到不支持的 32 位图片。*

## 2. 核心功能

1. **自动调整分辨率**：统一使用高质量的 `LANCZOS` 采样算法将图片缩放至严格的 `640x480` 大小。
2. **格式标准化**：将图片强制存为无压缩的 Windows Bitmap (BMP) 格式，色深固定为 24 位（8-bit Red, 8-bit Green, 8-bit Blue）。
3. **双重运行模式**：支持一键式批量转换文件夹，也支持命令行精确指定单文件转换。

## 3. 环境准备

运行此脚本需要电脑上安装有 Python 3 及 `Pillow` 库。
你可以通过以下命令快速安装依赖：
```bash
pip install Pillow
```

## 4. 使用方法

### 模式一：批量转换（推荐）
如果你有很多图片需要一次性转换：

1. 双击运行 `convert_images_to_bmp.py`，或在终端中执行：
   ```bash
   python convert_images_to_bmp.py
   ```
2. **首次运行**时，由于没有图片，脚本会在同级目录下自动创建一个名为 `input_images` 的文件夹。
3. 把你需要转换的所有图片（支持混合格式）复制到 `input_images` 文件夹中。
4. **再次运行**脚本，转换成功后，脚本会自动生成一个 `output_bmp` 文件夹。
5. 将 `output_bmp` 文件夹里新生成的 `.bmp` 图片全部拷贝到你的 TF 卡根目录下即可。

### 模式二：命令行单文件精准转换
如果你只想转换一张图片，并指定输入/输出路径，可以在终端或命令行（cmd/powershell）中使用如下格式：
```bash
python convert_images_to_bmp.py <输入文件> <输出文件>
```

## 5. 高级功能：SD卡一键同步防死锁脚本 (`sync_to_sd.py`)

在向 FPGA 用的 SD 卡拷贝新图片时，直接在电脑上“删除旧图片再拷贝新图片”往往**无效**。因为普通删除操作只会清除文件系统记录，而 FPGA 是采用“物理扇区扫描”的，残留在底层扇区里的旧图片（甚至已损坏的图片）依然会被 FPGA 识别，导致显示旧图或直接死机卡死。

为此，提供了一个专门用于同步 SD 卡的脚本：`sync_to_sd.py`。

### 功能说明
该脚本会自动执行以下三个步骤以确保 FPGA 读取正确：
1. **防物理残留**：扫描 SD 卡，把里面所有 BMP 图片开头的标识符（`BM`）破坏掉。这样即便物理数据残留，FPGA 也会直接跳过它们。
2. **彻底清空**：删除 SD 卡上的所有可见文件和文件夹，腾出空间。
3. **安全同步**：从你转换好的 `output_bmp` 文件夹中提取最多 4 张图片，按顺序写入 SD 卡，并自动加上数字序号前缀，让 FPGA 能以最快速度连续读取。

### 使用方法

将 SD 卡插入电脑，假设它被识别为了 `E:` 盘。
在终端或命令行中执行：
```bash
python sync_to_sd.py E:
```

你也可以通过参数指定其他图片来源文件夹或修改同步数量（例如只要 2 张图）：
```bash
python sync_to_sd.py E: -s "C:\my_images" -n 2
```

执行完毕后，安全弹出 SD 卡插入 FPGA 即可。

## 6. 保分辨率转换脚本 (`keepres_to_bmp.py`)

`convert_images_to_bmp.py` 会把图片**强行缩放到 640×480**（比例不对会被拉伸）。如果你要的是**原始分辨率一点不丢**，用 `keepres_to_bmp.py`：它只做色彩模式归一化，宽高原样保留，写出的仍是工程要求的 24 位无压缩 BMP。

### 它与前者的区别

| | convert_images_to_bmp.py | keepres_to_bmp.py |
|---|---|---|
| 尺寸 | 一律缩放成 640×480 | **保持原尺寸**（边长 ≤ 4096） |
| 画面比例 | 直接拉伸，可能变形 | 不变形；板上由 `bmp_view` 等比缩放 + 补黑边 |
| 预处理 | 无 | 自动应用 EXIF 旋转、动图取首帧、透明区合成底色、16 位灰度正确降位深 |

### 使用方法

```bash
python keepres_to_bmp.py                          # 一键：脚本旁 input_images/ -> output_bmp/
python keepres_to_bmp.py 1.jpg                    # 单文件 -> 同目录 1.bmp
python keepres_to_bmp.py pics/ -o out/            # 整个目录
python keepres_to_bmp.py a.png b.webp c/ -o out/ --short-names
```

常用参数：`-o` 输出目录、`--bg white` 透明区垫白（默认黑）、`--short-names` 生成 8.3 短名、`--overwrite` 覆盖同名。

### 几个要点

- 上限按 RTL 判据取 **4096**；不要顶到 4096（`bmp_loader` 用 12 位行号，0x1000 会被截成 0），高度建议 ≤ 4095。
- 不缩放意味着卡上文件更大：1536×1024 一张约 4.5 MB。
- 转换后会自动回读 BMP 头校验（`BM` / 24 位 / 不压缩 / bottom-up / 文件长度 = 54 + stride×H），不合格当场报错。
- 文件名同样建议 8.3 短名（FPGA 只扫短名），`--short-names` 会输出 `img0001.bmp`。

## 7. 卡上文件"扫不到"怎么查 (`check_sd.py`)

拷进去却不显示时，别猜——用 `check_sd.py` 按 RTL 的规则把根目录"重放"一遍。脚本**只读**，不改卡上任何字节。

```bash
python check_sd.py E:                       # 查卡（建议右键"以管理员身份运行"）
python check_sd.py E: --all                 # 连 wav/txt/子目录一起列
python check_sd.py ..\sim_data\fat32_10img.img   # 也能查磁盘镜像
```

它复刻的是 `SD/fat_dir_lister.v` + `SD/bmp_loader.v` 的真实判据：

| 判据 | 违反后的现象 |
|---|---|
| 只扫**根目录**（`INCLUDE_DIR=0`） | 放进文件夹里的图永远扫不到 |
| 只扫根目录首扇区起**连续 64 个扇区**（`FAT_MAX_SECS=64`） | 目录项太多 / 目录簇不连续 → 后面的项扫不到 |
| 扩展名逐字节比**大写 `BMP`**（无大小写折叠） | 名字能看到，相册/四宫格跳过，装载器不启动 |
| 属性 `0x02`（隐藏）直接跳过 | macOS 拷的文件常带隐藏位 |
| 遇 `byte0==0x00` 立即当目录结束 | 目录里有空洞 → 空洞后面全部消失 |
| 文件页 4 项/页、相册 3 张/窗口 | 第 4/5 张以后要翻页或滑动窗口 |
| `bmp_loader` 按 `file_offset+n` **连续读**、不跟簇链 | 文件碎成多段 → 头能过、花屏/黑屏/半张图 |
| 文件起点必须在前 **4 GiB**（23 位扇区号） | 大卡上靠后的文件读不到 |

卡本身也要对：**FAT32（不能用 exFAT/NTFS）**、512 字节扇区、根目录簇号 = 2。
