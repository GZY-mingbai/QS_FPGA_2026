# osd_bitmaps.bin 读取指南（RGB565 图标 + ARGB logo）

OSD 位图 ROM 的打包格式与解码方法。取代旧的 `icons32.bin`（4bpp 覆盖率 + 调色板）。

| 项 | 值 |
|---|---|
| 文件 | `icons/osd_bitmaps.bin` |
| 大小 | **30976 字节（0x7900）** = 7744 个 32bit 字 |
| 烧录位置 | Flash `0x050000`（`FlashProgrammer/host/partitions.json` 的 `osd_bitmaps` 分区，size `0x8000`） |
| 片上 | `osd_icon_rom.v` 的 `mem[0:7743]`，8 个 32Kb 块 |
| 加载 | 上电**一次** `fl_req`（30976 B ≈ 9.9ms @25MHz SCLK），之后不再碰 Flash |
| 生成 | `python tools/gen_osd_bitmaps.py --check` |

> ⚠️ **改了格式必须重烧这个分区。** 图标和 logo 共用一次搬运、一个 `data_pgm`
> 判定 —— 不烧的话**导航图标也会一起消失**（旧版只掉图标）。

> ⚠️ **`0x03D000` 的旧 icons 分区已作废**（4bpp 覆盖率，不再读取）。
> 留着不烧即可，不影响任何东西。

---

## 1. 为什么不再是「4bpp 覆盖率 + 调色板」

旧格式每个像素只存 0..15 的覆盖率，颜色靠 `osd_gfx.pal_rgb()` 查表。那个函数是
**32 项 × 24bit 的常量 case**，综合出来 ≈180 个 LUT，而且还在像素通路上压了
4~5 级 LUT —— 比它省下来的 BRAM 贵得多（本设计 LUT 一度到 95.38%）。

改成直出色彩后，像素通路只剩「选半字 + 拼回 888」（纯连线），**净省约 145 个 LUT**；
代价是 ROM 从 640 字涨到 7744 字（32Kb 块 1 → 8，池子 4/16 → 12/16）。

## 2. 两种子格式（故意的）

| 区域 | 格式 | 为什么 |
|---|---|---|
| 图标（10 张 32×32） | **RGB565，2 像素 / 32bit 字** | 图标是"不透明贴片"（底板 + 墨色），alpha 恒 255，16bpp 就够 |
| logo（64×41） | **ARGB8888，1 像素 / 32bit 字** | 背景必须和左栏面板一样是 **75%（#0E0E0E, A=192）**，需要逐像素 alpha |

**logo 为什么非要 alpha**：`ps_merge_alpha_pp` 算的是 `a9 = A × fade / 256` ——
像素自带的 A **是参与混合的**。面板是 A=192（75%），logo 背景若写成 A=255 就变成
一块**实心** #0E0E0E：面板下面那 25% 的视频透不上来，屏幕上就是一个方框
（这一版就是这么被抓到的 —— 断言全绿，出图一眼看出矩形）。

生成工具按 **source-over** 预合成好：

```
A = 192 + 63·c
C = [c·ink + (1-c)·0.75·#0E0E0E] / (A/255)
```

`c` = 覆盖率（SVG 8× 超采样，64 级）。c=0 ⇒ A=192、C=#0E0E0E（**和面板逐位相同**）；
c=1 ⇒ A=255、C=墨色。

## 3. 内存布局

```
word  0     .. 511    icon0 普通态 32×32   （512 字 = 1024 px，16bpp）
word  512   .. 1023   icon0 激活态 32×32
word  1024  .. 1535   icon1 普通态
word  1536  .. 2047   icon1 激活态
      ...             （5 图标 × 2 态 = 5120 字）
word  5120  .. 7743   logo 64×41           （2624 字 = 2624 px，32bpp）
```

图标顺序 = `display / album / files / settings / about`，每个紧跟"普通态 → 激活态"。

## 4. 地址公式（osd_gfx 里几乎全是连线）

```
图标：addr = {idx[2:0], act, ly[4:0], lx[4:1]}          // 0..5119，纯拼接 0 LUT
      像素 = lx[0] ? word[31:16] : word[15:0]          // 低半字 = 偶像素

logo：addr = 5120 + {ly[5:0], lx[5:0]}                  // 5120..7743，1 像素 1 字
           = {~(x[11]&x[10]), x[11]^x[10], ~x[10], x[9:0]}   // x = ly*64+lx，4 LUT
      像素 = 整个 32bit 字 = {A8, R, G, B}             // 不选半字、不查表
```

`5120 = 0x1400 = bit12 + bit10`，而 `x ≤ 0xA3F` ⇒ 只有 bit10..12 会进位，
所以加法退化成 3 个门。

## 5. 字节序

`osd_icon_rom` 的拼装是 `shf <= {fl_data, shf[31:8]}` ⇒ **文件里第一个字节落最低字节**：

| 区域 | 文件字节序（每 4 字节） |
|---|---|
| 图标 | `B0,G0,B1,G1`（两个 16bpp 小端像素：偶像素在前） |
| logo | `B,G,R,A` |

所以图标区就是"16bpp 光栅序、小端"，可以直接和一帧 RGB565 贴图对照。

## 6. 关键样本（烧录后可直接比对）

| 位置 | 期望 |
|---|---|
| 文件长度 | `30976`（`0x7900`） |
| `word0` | `BDF7BDF7`（icon0 底板 #C0C0C0 的 565） |
| `word512` | `341F341F`（icon0 激活态底板 #3080FF 的 565） |
| `word5120` | `C00E0E0E`（logo 左上角：A=192 + #0E0E0E） |
| `word7743` | `C00E0E0E`（logo 右下角） |

`logo alpha`：A=192（纯背景）1181 个，A=255（纯墨）875 个，中间过渡 568 个。

## 7. 565 量化误差

| 项 | 误差 |
|---|---|
| 图标底板 #C0C0C0 | → #BDBEBD，Δ3 |
| 图标墨色 #161616 | → #111111，Δ5（比旧的 4bpp 16 级最大误差 6 还小） |
| 图标激活底板 #3080FF | → #3182FF，Δ2 |
| logo | **无量化损失**：32bpp，颜色逐位保留 |

## 8. 重新生成

```
python tools/gen_osd_bitmaps.py --check
```

输入：`icons/png32/ico-*.png`（10 张 32×32）+ `icons/logo_ph1.svg`
输出：`icons/osd_bitmaps.bin` + `APP/OSD/tools/osd_bitmaps.hex`（仿真用）

`--check` 会把 10 张图标 + logo（分别铺在面板色和亮底上）拼成对比图存到
`tools/out/osd_bitmaps_check.png`，并打印：文件长度、两种区域的字数、
alpha 分布、往返一致性、关键样本。

> 换 logo 只改 `logo_ph1.svg` 重跑即可 —— 尺寸常量在脚本头部（`LOGO_W/LOGO_H`）。
> ⚠️ 改尺寸必须同步 `osd_menu.v` 的 `LOGO_W/LOGO_H` 和 `osd_gfx.v` 的地址公式
> （`{lg_ly[5:0], lg_lx[5:0]}` 假设宽 64、高 ≤64）。

## 9. 烧录

```json
{ "name": "osd_bitmaps", "offset": "0x050000", "file": "../../icons/osd_bitmaps.bin", "size": "0x8000" }
```

字体（`0x000000`）和提示音（`0x040000`）分区不受影响，不用重烧。
