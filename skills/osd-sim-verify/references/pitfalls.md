# 踩坑清单（iverilog / TD / OSD 布局）

每条都是**真踩过**的：现象 → 原因 → 改法。按"最容易被仿真骗过去"排序。

---

## 1. `always @(*)` 的敏感表不含函数体内读到的信号

**现象**：仿真里 `val2` 已经改成 0 了，取出来的 `item_val` 还是 1；上板却是对的。
**原因**：`function val_of(item)` 体内读 `val0..val6`，iverilog 生成敏感表只看**调用处**
写出来的标识符（只有 `item`）⇒ 改 val 不会触发重算。综合成纯 MUX，所以上板对。
**改法**：取多路值一律写成 `always @(*)` + 显式 `case`（块内直接读 val0..val6），
或者写成行内表达式。**这条最危险：仿真"验证"了整个失效。**

---

## 2. 一元 `~` 被上下文撑宽

**现象**：勾选框永远勾着，按上/下不翻转；抓到的值在 1 / 126 / 127 之间跳。
**原因**：`val3 <= ~val3[0]` —— 目标 7 位，一元 `~` 的操作数被撑到 7 位再取反
⇒ `1 → 126`，再取反 `126 → 127`，恒非零。
**改法**：显式三目 `val <= (val != 0) ? 0 : 1`，或 `val <= ~{6'd0, val[0]}`。

---

## 3. 位宽截断（函数返回值 < 常量宽度）

**现象**：12 个"两字"标签全部空白，四字标签正常。
**原因**：`function [159:0] label_of` 里写了 192 位常量（3 个字）⇒ 高位被丢。
**改法**：函数位宽按"实际最长字数 × 16"给，并让取字下标与位宽一致
（本工程 `label_of` 收到 64 位 = 4 字，取字用 `txt_c[1:0]`）。

---

## 4. 多驱动：iverilog 不报，TD 直接失败

**现象**：`ERROR: net 'ch_i[2]' is constantly driven from multiple places`。
**原因**：同一个 reg 在**动画块**（复位）和**布局状态机块**里各赋值一次。
**改法**：一个信号只在一个 always 块里驱动。改完跑静态检查：

```bash
$PY tools/chk_multidrv.py osd_menu.v osd_gfx.v osd_cellmem.v osd_widget.v osd_top.v
```

它会同时查"过程/连续赋值冲突"和"同块重复驱动"，全 `ok` 才交给综合。

---

## 5. `for` 循环 + 变量位选，TD 可能展不开

**现象**：仿真正常，上板该段逻辑无效（或综合直接报错）。
**原因**：`txt_col[lcnt*32 +: 32] <= ...`（part-select 的基址是循环变量），
TD 前端不保证能展开。
**改法**：**展开写死**（5~8 行，可读性反而更好）。同理，`always @(*)` 里不要调
"读了很多外部信号"的 function（见第 1 条）。

---

## 6. 文字层 16px 字格互相擦除（最隐蔽）

**现象**：下拉弹层"低"字的**最上面 4 行没了**；换一版后变成"高"的最下面 4 行没了。
**原因**：文字层每个字格 16px 高。两条文字行 y 相差 < 16 时，后画的那条把前一条
的像素**擦掉重合部分**。行距 34 时最外侧选项离控件行 `2*34=68`，而菜单行距 80
⇒ `80-68 = 12 < 16` ⇒ 重合 4 行。
**改法**：弹层行距必须满足 `2*PITCH <= 菜单行距 - 16`（本工程 32 ≤ 64），
即**行距 32 是上限**。并用不变量断言守住：`chk_txt_noclash`（任意两行的字格不许相交）。

---

## 7. 窗口行号 ≠ 绝对 item 号

**现象**：没滚动时一切正常；**滚到底**再开下拉，被弹层盖住那行的标签和数值从弹层
底下透出来（截图里"色彩空间"和一个游离的"中"）。
**原因**：`sel_k / icx / pop_wx0 / pop_wx1` 全是**窗口行号**（0..4），
而 `vidx` 是 **item 号**（0..6）。两者只在 `scroll_row == 0` 时相等。
**改法**：文字侧统一用 `vrow = txt_l - 1`；控件侧用 `icx`。永远不要拿 `vidx`
去比 `sel_k`。

---

## 8. 不透明细线与半透明底并排 ⇒ "杂像素/虚线"

**现象**：分割线沿竖直方向一会儿暗一会儿亮，上板看是"杂线/虚线"，仿真出图看不出来。
**原因**：分割线 `level 8`（不透明 `3A3A3A`，恒 58），左右两侧面板是 `level 6`
（75% `0E0E0E`，颜色随底图变）。底图亮时面板 74 > 58 ⇒ 线偏暗；底图暗时面板 16 < 58
⇒ 线偏亮。**差值随底图反号**，于是看起来忽明忽暗。
仿真用平滑渐变底图，几乎不出现明暗突变，所以看不见。
**改法**：**相邻的细特征必须同 level**，只允许固定亮度差（本工程都改成 75%，
差 33 阶恒定）。用 `tb_osd_style` 的 A 组断言 + `slice.py` 的差值恒定性检验守住。

---

## 9. 页面板少一个状态 ⇒ 顶端一条亮带 / 四个角有圆角

**现象**：屏幕最上面 12px 明显比面板亮（"顶端没有 alpha 层"）；四个角有圆角。
**原因**：① `gy0=12` ⇒ 那 12px 只有全屏遮罩 50%，而面板 75%；
② 面板用 `Panel` 类型自带 1px 边框（不透明），在暗底上发亮，视觉上像"圆角边"。
**改法**：`gy0=0`（面板铺到屏幕顶端）+ 类型改 `Solid`（不画边框，边框交给分割线槽）
+ `grad=0`（圆角只在 `rad≠0` 时才会切）。

---

## 10. `shot_rect` 只能缩小，不能放大

**现象**：想放大看 1px 边框，结果越放越小/不变。
**原因**：`shot_rect(name, x0, y0, nx, ny, st)` 的 `nx,ny` 是**输出尺寸**，
`st` 是采样步长（`x = x0 + i*st`）⇒ `st>1` 是**缩小**。
**改法**：出图用 `st=1`，再 `tools/crop.py in.ppm out.png x y w h 6` 放大。

---

## 11. `crop.py` 越界 → 写出坏 PNG → 整轮对话 400

**现象**：读图报 `unsupported image ... webp, png, jpeg, gif`，换哪张都一样。
**原因**：裁剪矩形越界时像素切片变短，但 IHDR 仍按 `w*h*k` 声明 ⇒ 头尾不一致。
**改法**：`crop.py` 已加夹紧 + 长度断言；读图前跑一遍 `image-tools.md` 里的
PNG 校验脚本（CRC + 解压长度），坏图直接重生成。

---

## 12. 等帧数不够 ⇒ 拍到"半新半旧"，看起来像布局 bug

**现象**：巡检四页文字时，标签比控件高一行、或某些标签空白，改代码怎么都对不上。
**原因**：`NL` 从 6 加到 8 后文字重绑变慢，台子里等 24 帧不够，拍到了"上一页标签
+ 这一页标签"的混合。
**改法**：巡检等待改成 60 帧。**凡是"图看起来错位"先怀疑拍在了动画/重绑中途**，
用 `dump_state` 确认状态，再调等待帧数，最后才怀疑布局。

---

## 13. 同一个 `out/*.ppm` 文件名被不同台覆盖

**现象**：明明重新渲染了，图却没变。
**原因**：`tb_osd_popup` 和 `tb_osd_render` 都写 `out/f_seam.ppm`，后跑的覆盖前者。
**改法**：跨台复用的图用不同前缀；或整目录改名保留一轮结果。
出图后 `ls -la --time-style=+%H:%M` 对一下时间戳再下结论。

---

## 14. 场景侧"忘了某个状态"（跨模块，仿真抓不到）

**现象**：主页播过切换动画后，再打开 OSD，**菜单背景是黑的**（fx2 淡入淡出例外）。
**原因**：`viewer_ctrl` 的 `arm_geom` 只列了 `S_ARM / S_LOW / S_STUCK`，
**漏了 `S_OSD`**。S_OSD 相位 0 把 `a_hd` 拉 0 ⇒ A 从"满屏的 HD 通路"切回
"吃 `a_pos` 的缩略图通路"，而 `a_pos` 还是动画末帧的出屏坐标
（fx0 X0=±640、fx1 Y0=±480、fx3/fx4 后半段也出屏；**fx2 的 A 恒在 (0,0)**）⇒
`ps_gen_image` 框外恒输出 0 ⇒ `pix_a` 全黑 ⇒ 75% 半透明的菜单底下就是黑的。
**改法**：把 `S_OSD` 加进 `arm_geom`（`pos/size/k` 三个一起钉，只钉 `pos` 会缩放错）。
**教训**：这类问题横跨 `viewer_ctrl × viewer_fx × viewer_scene × ps_gen_image`，
`tb_osd_*` 只例化 `osd_top`，**结构上不可能复现** —— 要读代码找，
再用"fx2 不黑 vs 其它黑"这种可上板验证的判据确认，最后把它变成一条断言或注释里的不变量。

## 15. 共享控制器的"长度"必须锁存，否则第二个客户的传输会提前收尾

**现象**：OSD 导航图标全部是**纯色色块**（5 张 4bpp 覆盖率图没有形状），
字库文字正常；`osd_icon_rom.ready=1`（说明"读过 Flash 且不是全 0xFF"）。

**原因**：`flash_arb` 的 `fl_len` 是**组合选择**（看当前谁在请求）。
`osd_icon_rom` 发完单拍 `req` 就进接收态、`req` 撤销 ⇒ `fl_len` 立刻回落成
字库客户的 **32**。而 `spi_flash_read` 的 `rx_last` 比较的是**端口上的 `rd_len`**：

```verilog
wire rx_last = (state == ST_RX) && (rx_cnt == (rd_len - 1));   // ❌
```

于是 2560 字节的图标传输在第 32 字节就"收满"，ROM 只写了前 8 个字，
其余保持上电值（BRAM=0 ⇒ 覆盖率 0 ⇒ 底板色）⇒ 纯色块。
首字节是 0x00 ⇒ `data_pgm=1` ⇒ "未编程检测"也拦不住。
字库每次就是 32 字节，回落后仍是 32，所以只有图标暴露。

**改法**：收单那一拍把 `rd_len` 锁进 `len_r`，整段事务只用 `len_r`：

```verilog
ST_IDLE: if (rd_req && por_done && (rd_len != 0)) begin
             len_r <= rd_len;  state <= ST_TX;
         end
wire rx_last = (state == ST_RX) && (rx_cnt == (len_r - 1));   // ✓
```

**回归**：`tb_osd_icons.v` 把真实 `icons32.bin` 灌进 Flash 模型，
逐像素比对 5 个 32×32 图标（改前 844/1024 错、整块同色；改后全 0 错）。
**通用教训**：任何"地址/长度/属性"在请求后还会变的共享总线，
接收侧必须**锁存整份请求**，不能只锁地址。

## 16. OSD 与 B 层动画共存：整层替换会擦掉动画

**现象**：打开信息条后按切换键，动画一开始信息条就消失（`info_show` 只在
`S_HD/S_STUCK/S_HDF` 为 1）。把 `info_show` 放宽到 `S_ARM/S_TRANS/S_LOW`
之后，**动画被擦掉**，只剩底图。

**原因**：`viewer_scene` 里 OSD 借用 B 层的合并口：

```verilog
pix_b_eff = osd_on ? osd_pix : pix_b;   // ❌ OSD 一开就整层替换 B
```

信息条矩形外 `osd_pix` 的 A=0 ⇒ 那一大片直接透出 A 层。

**改法**：逐像素择优（零延迟、零乘法）：

```verilog
osd_hit   = osd_on & (osd_pix[31:24] != 0);
pix_b_eff = osd_hit ? osd_pix : pix_b;              // 前景只有一种形态
alpha_eff = osd_hit ? ((A==192)?192:osd_fade) : alpha_q;
s2_b      = in_box_b_p & (alpha_q == 8'hFF);        // 背景：B 落屏就取 B
```

- A=0 的像素仍走 B ⇒ 动画不受影响；
- A!=0（文字/面板）幅度都交给合并级，`a9 = a1*alpha/256`；
- **背景由 `s2_b` 选**：B 完全落屏（`alpha_q=0xFF`）且该像素归 B ⇒ `s2=pix_b`；
  否则 `s2=pix_a`。面板在 A 区混 A、在 B 区混 B，两侧同一种混法；
- `alpha_b != 255`（S_ARM / fx2 淡入中）时**不要把 s2 换成 B**，否则面板会
  提前露出未淡入的 B。四宫格 `alpha_q` 恒 0xFF ⇒ 自动走 B。

> ⚠️ **2026-11-05 修掉的老坑**：更早的写法是"面板预混 B"——
> `pix_b_eff = {255,(3*O+B)>>2}`，指望"A=255 ⇒ 合并级直通"。
> 但面板这档 `alpha_eff` 是 **192**，合并级算 `a9 = alpha = 192`（≠256）
> ⇒ 结果又被 A 层混了 25%；动画期间该处 A 为空(0) ⇒ 面板背景混进 57% 的黑
> ⇒ 上板"信息条被切成深浅两块（竖缝在右/横缝在底部）"。
> 实测（`ps_merge_alpha_pp` 真值）：A 区 119、B 区 65，修后两侧都是 119。
> **教训**：任何"先自己混一次、再交给合并级"的写法，都要先确认
> `a1=255` 时 `a9` 真的等于 256（`alpha` 也必须是 255），否则就是混两次。

**回归**：`tb_info_overlay.v`（force 内部 `pix_b/in_box_b_p`，逐值检查
`pix_b_eff / s2_b / pix_a_eff / alpha_eff`，18 项）+ `tb_info_trans.v`
（S_ARM/TRANS/LOW 全程 `info_show=1`，5 项）。

## 17. 320×240 → 640×480 的"微量左右位移"：奇数宽 + 左沿采样

**现象**：fx3 后半段把缩略图从 320×240 放大到 640×480 时，画面有 1~1.5px 的
横向漂移；变高清那一瞬也会跳一下。

**原因**（两层叠加）：

1. `viewer_fx` 的 `g320 = eu*640>>9` 逐 1px 变化，奇数宽时框中心落在 x.5，
   而 `pos = 160 - g160` 只能整数 ⇒ 框中心本身抖 ±0.5px；
2. `ps_gen_image` 的 `map_src` 用 `mx = lx*kx`（**左沿**采样）⇒ 内容整体
   偏右半像素，且随 `kx = floor(160*65536/W)` 的取整抖动。

**改法**：

- `viewer_fx`：`g320/g240` 强制偶数（`& ~1`），`g160 = g320/2`、
  `g120 = g240/2` ⇒ 框中心恒 320/240。参数 `FX3_EVEN=0` 可回到旧行为
  （只给 `tb_fx_equiv` 做逐值等价）。
- `ps_gen_image`：`mx = lx*kx + kx/2`（目标像素中心采样），参数
  `SAMPLE_CENTER=0` 可回到旧行为（只给 `tb_pgi_equiv`）。
  1:1（kx=32768）时选到的像素不变，只有非整数缩放改相位。

**量测**：`tb_scale_center.v` 用两个关于源中心对称的白标记，逐级量
亮度中心；改前 max 1.5px，改后 max **0.5px**（fx3 实际偶数宽序列）。
**教训**：这类"差半像素"必须用**对称双标记的中点**量，单标记会被
"源像素本身偏离中心 0.5px"骗过去。

## 18. 列号比较被 4 位 `tc` 截断：`tc == 4'd17` 其实是 `tc == 1`

**现象**：把信息条倒计时挪到第 17/18 列（右对齐）后，仿真里倒计时数字
跑到第 1/2 列去，把分辨率的第一位数字盖掉。iverilog 只给
`warning: Numeric constant truncated to 4 bits`，非常容易漏看。

**原因**：`osd_menu` 的 `resfmt` 块里为了省位宽声明了 `reg [3:0] tc;`
再 `tc = txt_c[3:0];`，后面所有列判断都写成 `tc == 4'dN`。列号一旦超过 15，
`4'd17` 被截成 `4'd1`，于是"第 17 列"和"第 1 列"成了同一个分支。

**改法**：**凡是可能 ≥16 的列号，一律拿原宽度的 `txt_c`（5 位）比**；
`tc = txt_c[3:0]` 只留给"W/H 位号"这种天然 <16 的用途，并且那几支要
额外用 `txt_c < 5'd12` 兜住，防止第 17/18 列误入。

**教训**：TD/iverilog 对常量截断都只是 warning。改完含数字常量的分支后，
`grep -i "truncated" 编译日志` 应当成为固定动作。
（本轮就是靠这条 warning 才发现补丁根本没生效。）

## 19. 按键语义一翻转，散落在多个段落里的"方向断言"全变陈旧期望

**现象**：把 ComboBox 的方向改成"KEY4 向上（值 −1）/ KEY3 向下（值 +1）"
之后，`tb_osd_keys` 一次冒 **30 项 FAIL**。

**误判风险**：FAIL 里混着两类，很容易被当成 RTL 的新 bug：

1. 值断言：`val4 -> 1 : got 0, expect 1`、`lang 1->0 : got 2, expect 0`
   —— 方向反了，是**期望陈旧**；
2. 几何断言：`H sel item on combo row : got 410, expect 378`、
   `H panel top : got 372, expect 340`、`H5 anchor c0 : got 52958, expect ...`
   —— 看着像布局 bug，其实是"值没动 ⇒ `pop_sel` 没变 ⇒ 弹层没上移一格"，
   同样是期望陈旧（每项都差 **恰好一行 32px** 或 **一个选项的码值**）。

**怎么快速归因**：把 FAIL 分成"值/几何"两组，看几何误差是不是**整数倍行距**
且方向一致；若是，先修值断言的按键，几何断言会自己跟着过。

**根因（工程习惯）**：同一个测试台里历史上有过两套方向约定（H 段用
KEY4=+1、O 段用 KEY3=−1），说明"按键方向"这件事**没有单一出处**。
改法上除了改 RTL，还要在 tb 每段前面写死一行注释
`// KEY4=上（−1）、KEY3=下（+1）`，否则下次再翻又会散。

## 20. 文字列"右对齐"要按面板几何反算最后一格，不能凭感觉

**算式**（信息条，`osd_widget` 的 cell16 = `gx0=8, gx1=328`、
文字行 `X0=16`、格宽 16）：

```
第 c 格占 x = 16 + 16c .. 31 + 16c
c=18 → 304..319   （右边留 8px，与左侧 8..15 的留白对称） ✓
c=19 → 320..335   （越过 gx1=328）                        ✗
```

⇒ 最后一格是 **18**，`ctl_len` 必须是 **19**（`len_px = 19<<4 = 304`，
`LX = x−16 < 304` 正好把第 18 格包住）。两个数字**必须成对改**：
只改文字位置不改 `ctl_len`，右边最后一格会被 `LHIT` 切掉（看着像"数字缺一半"）。

十位/个位右对齐的写法：个位**永远写**（它是锚），十位为 0 时写空白码
`16'h0000` —— 于是 0/7/30 都贴右沿。

## 21. 打包分量（RGB565/RGB888）**禁止整字相加/移位**做平均、缩放、淡入淡出

**上板现象**：640×480 源在 **320×240（565）状态下整幅花屏**，但苹果/草莓的轮廓
一眼认得出；OSD 文字正常，HD（888）正常。

**病根**（`bmp_scale.v` 的 2:1 横向平均）：

```verilog
pix_avg_sum = {1'b0,pix_even} + {1'b0,pix_lat};   // 24 位整字相加 ← 错
lbuf[...]  <= pix_avg_sum[24:1];                  // 再整体右移   ← 错
```

R/G/B 挤在同一个 24 位字里 ⇒ 低位通道的和 ≥256 就进位到高位通道，右移时高位
通道的奇偶位又落进低位通道的 MSB：

```
(R_s<<16 + G_s<<8 + B_s) >> 1 = R_s<<15 + G_s<<7 + B_s>>1
   R = R_s>>1              ✅
   G = {R_s[0], G_s[8:1]}  ❌ MSB 被 R 的奇偶覆盖
   B = {G_s[0], B_s[7:1]}  ❌ MSB 被 G 的奇偶覆盖
```

判据非常好记：**`avg(24'h010000, 24'h000000)` 应该还是红色，旧写法得到
`24'h008000`（凭空冒出 G=128）**。上板就是 ~50% 像素蓝/绿各 ±128 的彩色麻点，
红色/亮度结构保留 ⇒ "花的，但能看出图像大概是什么"。

**改法**：逐通道加，最后拼回去（3 个 8 位加法器，比 1 个 25 位加法器还省）：

```verilog
wire [8:0] avg_r = {1'b0, a[23:16]} + {1'b0, b[23:16]};
wire [8:0] avg_g = {1'b0, a[15:8]}  + {1'b0, b[15:8]};
wire [8:0] avg_b = {1'b0, a[7:0]}   + {1'b0, b[7:0]};
wire [23:0] pix_avg = {avg_r[8:1], avg_g[8:1], avg_b[8:1]};
```

**反例对照**：`viewer_scene` 的面板混色是对的 ——
`{1'b0,R,1'b0} + {2'b0,R} + {2'b0,B}` 先把每个通道**左移对齐到自己的位段**
再加，最后 `[9:2]` 右移，通道之间不可能串位。同一份代码库里两种写法的差别，
正好说明这不是"风格问题"而是"对不对"的问题。

**为什么仿真当时是绿的（这条更重要）**：测试台的期望函数

```verilog
function [23:0] avg2pix;  t = {1'b0,a} + {1'b0,b};  avg2pix = t[24:1];  endfunction
```

**抄了 RTL 的表达式** ⇒ 把 bug 写成了期望，30/30 假绿。

**规则**：
1. 期望必须从**规格**写（"两个像素逐通道取均值"），不要从 RTL 翻译；
2. 再加一条**不依赖实现**的断言兜底：`avg(纯红, 黑)` 的 G/B 必须为 0，
   `avg(纯绿, 黑)` 的 B 必须为 0。这类"不许变出新颜色"的断言，比逐值比对
   更能抓住串位/溢出/位段错。

## 22. 拼接里的 `integer` 表达式按 32 位自决定宽度 ⇒ 期望函数整体错位

**症状**：写一个坐标编码图的参考函数

```verilog
function [23:0] srcpix;
    input integer x, y;
    srcpix = {x[9:2], y[8:2], x[1:0], y[1:0], 4'h0};   // ✗
endfunction
```

`x=4, y=0` 得到 `0x008000`，而规格是 `0x010000` —— 整体右移了 1 位。

**根因**：`input integer` 是 32 位；`integer` 上的表达式/位选在拼接里按
**32 位自决定宽度**，`{8b, 8b, 2b, 2b, 4b}` 的意图被扩成
`{32b, 32b, 32b, 32b, 4b}` 再截断到 24 位 ⇒ 高位全被裁掉、整体错位。

**修法**：先在函数内落成定宽 `reg`，再拼：

```verilog
function [23:0] srcpix;
    input integer x, y;
    reg [7:0] xh, yh;
    reg [1:0] xl, yl;
    begin
        xh = x >> 2;  yh = y >> 2;
        xl = x & 3;   yl = y & 3;
        srcpix = {xh, yh, xl, yl, 4'h0};               // ✓
    end
endfunction
```

**代价**：我在 `tb_bmp_read640` 上先踩了这个坑，看到 `got=010000 / exp=008000`
就以为是"bmp_read 偏了 16 列"，差点又去改 RTL。判据：**如果"不匹配"的点
分布是"从某个 x 起整幅错"，先怀疑期望函数；如果是"从某个 x 起内容错位
但值合法"，才怀疑 RTL。**

> 与第 21 条同一个教训的两个面：**期望值必须从规格独立写，且写完先让它
> FAIL 一次再相信它**。这次是先跑出 FAIL 才发现是期望错，运气好。

## 23. 流控冻结必须冻结**整条**流水线：只冻前半段会让流水线"塌一格"

**上板现象**：源图 640×480，**HD（888）右边一条贯穿全高的 1px 黑线**，565 没有；
烧回 `d1b08f8`（还没有缩放）就没有 ⇒ 缩放这条线引入的回归。

**根因**（`SD/bmp_scale.v` 的 `S_FL` 冲刷）：

```verilog
// 原来：ox / d1_* 在 if(!stall) 里（会被冻结）
if (!stall) begin
    lb_ra <= xr(ox); d1_col <= ox; ox <= ox+1;
end
// 但这两句在 always 块顶部，**无条件**推进
lb_q   <= lbuf[lb_ra];
d2_col <= d1_col;
```

冲刷是"取址 → BRAM 输出 → 写"两级流水，`d2_col` 比 `ox` 晚 2 拍、与 `lb_q` 配对。
`stall` 一来：`ox` 停在 K、`d1_col` 停在 K-1，而 `d2_col` 继续吃 `d1_col`
⇒ 从 K-2 **追上** K-1 ⇒ 流水线塌一格 ⇒ **第 K-2 列永远不写、第 K-1 列写两遍**。

**板上证据（仿真复现）**：给 `tb_scale_shift` 加上 `stall` 激励后，写地址序列
```
#7 woff=7
#8 woff=9      ← 8 被跳过
#9 woff=9      ← 9 写两遍
```
每行 46 个列是"从未写入"的洞（帧缓存/纹理都不预清，永远是上电值 0 ⇒ 黑）。

**为什么只有 888 看得见**：冲刷循环对两种格式都是 `ox = 0..641`（642 拍），
但 **888 每行写 640 字、565 只写 160 字**（1 字 = 2 像素）⇒ 888 的写 FIFO
水位是 565 的 4 倍，**行末正好撞上 `scale_stall`** ⇒ 第 639 列被跳过
⇒ 一条贯穿全高的黑线。565 数据量只有 1/4，撞不到。

**修法**：把延迟线也放进冻结条件。

```verilog
wire fl_hold = (st == S_FL) && stall;
...
if (!fl_hold) begin
    lb_q   <= lbuf[lb_ra];
    d2_inb <= d1_inb;
    d2_col <= d1_col;
end
```

**验证**：`tb_scale_shift` 加 stall 激励后 12/12 PASS（改前每行 46 个洞）；
`tb_bmp_scale` 36/36、`tb_loader` 19/19 不受影响。

> **通用规则**：任何"`if (!stall)` 冻结前半段、后半段在别处无条件推进"的写法
> 都是同一个坑。冻结必须覆盖**所有**与流水相位相关的寄存器（数据、valid、
> 地址、列号、以及它们的延迟副本）。**写测试台时，反压信号一定要给激励**——
> 这个 bug 在 `stall` 恒接 0 的所有台里都是隐身的。

## 24. 三维小整数判据折成查表时，**先证明状态数**再定位宽

**背景**：`osd_widget.v` 的圆角判据 `cut / arc / arc2` 由
`rq`（≤8）、`dxm`、`dym` 三个 ≤8 的小整数决定，但算术实现是
"减→clamp→减→2 个 4×4 乘法→加→比较→再加→再比较"，**20 级逻辑 / 34.4ns**
（Fmax 28.7MHz，要求 50MHz，SWNS −14.784ns）。改成查表。

**第一版（能过但吃面积）**：`index = {rq[3:0], dx, dy}`，每项 3 位
`{cut, arc, arc2}` ⇒ **4096 bit**。两个浪费：
· `rq` 只有 1..8 八个有效值，用 4 位寻址**白扔一半表**；
· 3 位里绝不会有两位同时为 1，非法组合也占了地方。

**第二版**：半径改 `rq-1`（3 位）寻址 ⇒ 512 项；把三项折成 **2 位带序**
⇒ **1024 bit（1/4）**。能折的前提是"状态数 ≤ 4"，而这个前提**不是想出来的，
是算出来的**：

三条判据阈值**同为 `r²`**，只是 LHS 逐级变大
（`d2 < (uu+1)²+(vv+1)² < (uu+2)²+(vv+2)²`，`inc` 区里 `uu,vv ≥ 1`），
LHS 越大越容易越阈 ⇒ 集合关系是 **`cut ⊆ arc ⊆ arc2`**。
再叠加 RTL 里 `arc`/`arc2` 都被 `!cut` 门控，`inc` 区内的合法状态只剩 4 个：

| band | cut | arc | arc2 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 1 | 0 | 0 | 1 |
| 2 | 0 | 1 | 1 |
| 3 | 1 | 0 | 0 |

**踩到的两个坑**：

**① 蕴含方向搞反。** 我一开始认定"`arc2 ⇒ arc`"，于是把 `arc2` 解码写成
`band==1`。实际上 `arc2` 是 `arc` 的**超集**（LHS 更大 ⇒ 更容易成立），
`band==2` 时 `arc2` 也为 1。漏了这一项 ⇒ **96812 组不匹配**。
正确解码：`arc2 = !cut && band != 0`。

**② 打算用"生成器自检"证明状态数，结果自检本身写错了。** 第一版生成器里
`check()` 只比对最终三元组，它确实报了 96812 组不匹配 —— 但同一份代码里
我另写了个"嵌套性检查"，`if a2 and not a1: nest += 1`，把方向也写反了，
于是它报"36 例逆序"来**支持我的错误结论**。判据：**自检必须能独立地
说"不"**——把 `nest` 打印出来只是数字，得让它和"合法状态集合"这种
**结构化断言**（`states - legal` 必须为空）挂钩才可信。

**回归证据链**（都在 `skills/osd-sim-verify` 的台里）：

| 层 | 台 | 结果 |
|---|---|---|
| 组合判据逐位等价 | `tb_corner_equiv`（rad 0..15 × w,h 2..20 × lx × ly = 698896 组） | v1/v2 都 ALL PASS |
| 同上，扩范围 | `-DWHMAX=48`（2209 万组） | ALL PASS |
| 灵敏度 | 把 `rq` 上限 8→7 | 立刻 FAIL 并列出 `rad=8` 反例 |
| 样式/圆角语义 | `tb_osd_style`（14 项，含 grad=0 四角实心） | ALL PASS |
| 菜单几何 | `tb_osd_keys`（340 项） | ALL PASS |
| **端到端出图** | `tb_auto_popup` 4 张 PPM，v1 vs v2 | **逐字节完全相同** |

> **通用规则**：把多维小整数判据换成查表时，
> ① 先用组合数学定**状态数**，别用 `3 位 × 2^n` 硬铺；
> ② 半径这类"有上限的连续量"用 `x-1` 寻址能直接省一半深度
> （`rq=8` 时 `rq[2:0]=000`，减 1 自然回绕成 `111`，不用额外判等）；
> ③ **带序编码解码时先问"这个信号是另一个的子集还是超集"**，
>    方向上错一位就是上万组不匹配，而且仿真不会崩，只会静默画错。
> ④ 端到端出图比对（PPM 逐字节）比逐点断言更容易说服人，成本却最低
>    —— 前提是**改前先存一份基准**。

## 25. 只取低 N 位时，别按全宽做算术 —— 但也别"看出规律就下手"

**背景**：phy 报告里 50MHz 域 SWNS −5.926ns、628 个违例端点，抽样 10 条最差
路径**起点全是同一个** `u_scene/u_scan_gen/x_reg[4]`，终点全在 OSD 的地址口。
25.6ns 里 **84% 是走线**（21.3ns）、逻辑 12 级、**最大扇出 148** ⇒ 不是逻辑深，
是布线拥塞（LUT 93.4%）。这条锥是：

```
px → 19 路窗口比较/编码 → hit_idx
   → ic_i → 5 选 1 的 ic_y0 → 9 位减法 → 拼 icon_waddr → 8 个 BRAM 的 addrb
```

**化简一：地址只要低位，就别算全宽减法**

```verilog
ic_lx = x[9:0] - 10'd32;      // 10 位减法
... {ic_ly[4:0], ic_lx[4:1]}  // 只取 [4:1]
```

`32` 是 32 的倍数 ⇒ `(x−32) mod 32 == x mod 32` ⇒ **`ic_lx[4:1] ≡ x[4:1]`**，
整个减法可以删掉。同理 logo 那一路 `(x−16)` 只取 `[5:0]`、`(y−8)` 只取 `[5:0]`
⇒ 10/9 位减法降成 6 位。

**化简二：取模之后与常量做减法，等价于异或**

图标的局部 y 是 `y − (72+80i)`，只取 `[4:0]`：

```
(72+80i) mod 32 = 8 + 16·(i 为奇数且 i<4)
⇒ y[4:0] − 8 − 16·sel
```

而模 32 下 `−16 ≡ +16 ≡ 异或 bit4` ⇒ 最后那一步是**一个异或门**，
于是 5 位减法与 `hit_idx` 无关（可以和 19 路比较并行算），
与 hit 相关的只剩一个 XOR —— 锥又短一级。

**★ 踩到的坑：看数据总结规律时漏了 `default` 分支**

我一看 y0 = 72/152/232/312/392 就是等差 80，直接写成"偶数 → 8、奇数 → 24"。
但 `ic_i` 是 `hit_idx[2:0] − 5` 的 3 位值，**5/6/7 走的是 case 的 `default`**
（392 ≡ 8），按奇偶判会把这三种情况算成 24 ⇒ **穷举报 4096 组不匹配**。

正确条件：`ic_i[0] & ~ic_i[2]`（只有 1 和 3）。

> **通用规则**：
> ① 拼接里只取低 N 位时，前面的减法/加法可以按 `mod 2^N` 化简，常常能整段删掉；
> ② 模 2^N 下 ±2^(N−1) 就是"异或最高位"，别让加法器去做这件事；
> ③ **从数据里看出的等差规律，必须在穷举里跑过再信**——尤其是有 `default`
>    分支的 case，`default` 往往不满足那个规律；
> ④ 判断"是逻辑深还是布线差"看两个数：`Data Path Delay` 里 net 的占比
>    （>70% 就是布线）和 `Max Fanout`。**逻辑级数不多但 net 占比高 ⇒ 别再加流水
>    线，去减 LUT / 减扇出 / 缩短组合链。**

## 26. 背压停顿：流水线里**任何一个**寄存器没被 `pixel_ready` 门控，就错一个像素

**上板现象**（这一条查了整整一天，值得全文记下来）：

- OSD 菜单左侧导航图标、logo、游标框的**右边一列**出现 1px 宽的**竖直虚线**
- **每帧固定在同一列**，一列内部随行出没（像虚线）
- 颜色是**白/蓝**（不是黑 ⇒ 不是"没画"，是**取错了数据**）
- 所有已有测试台**全绿**，改任何 RTL 都"完全没变"

### 26.1 为什么现有测试全绿

**所有测试台的 `pixel_ready` 恒为 1。** 这一类 bug 只在背压停顿时出现，
所以仿真里永远隐身。这不是"测试不够细"，是**激励维度缺了一整维**。

### 26.2 机理

`app_scan_gen` 的 `x/y` 是**下一个待消费像素**；流水线里的 `s1_px` 才是当前像素。
停顿时 `x/y` 保持（`else if (streaming)`，停顿走 else 保持），但 `x` 已经比 `s1_px`
**超前一拍**：

| 拍 | ce | `x`（下一个） | `s1_px`（当前） | `rd_geo` / `dob`（没门控） |
|---|---|---|---|---|
| T−1 | 1 | P | ← P | ← geo(P) / mem(P) |
| T | **0** | P+1 | 保持 P | ← **geo(P+1) / mem(P+1)** ← 多走一格 |
| T+1 | 1 | P+1 | 保持 P | geo(P+1) / mem(P+1) |

T+1 那拍 `pix` 是用「坐标 P + 几何 P+1 + 位图 P+1」算出来的 ⇒ **一个像素错**。
停顿如果每行落在同一个 x（图片 FIFO 见底），就是**每帧同一列**的错，
错的那个像素画法随该列内容出没 ⇒ 看着就是虚线。

### 26.3 三处，逐个补

| 位置 | 症状 | 修法 |
|---|---|---|
| `ps_gen_text` | 文字层（早前修过） | `pix` 条件加 `s1_valid`，元数据寄存器挂 `ce` |
| `osd_cellmem.rd_geo/rd_attr` | **cursor 右边 1px 竖虚线** | 读口 `always @(posedge clk) if (ce) ...` |
| `osd_icon_rom` 读口 | **图标 / logo 竖虚线** | 见 26.4 |

补上 `osd_cellmem` 那条之后，**cursor 的虚线立刻消失**，图标还剩 —— 因为位图
还有独立的一份输出寄存器。

### 26.4 BRAM 的输出寄存器没有 valid，只能"冻地址"

`EG_PHY_BRAM32K` 的 `oceb`（输出寄存器使能）在 `REGMODE_B="NOREG"` 下**被旁路，
接了也没用**（实测：`oceb(ce)` 上板毫无变化）。不能靠它。

也**不能**给输出加一级 `if (ce)` 寄存器 —— 那会多一拍，整条流水线要重排。

正解是**冻住送给 BRAM 的地址**，让它在停顿拍重复采样同一个字：

```verilog
reg  [12:0] ra_hold;
always @(posedge clk) if (ce) ra_hold <= ra_addr;   // ★ 必须 if(ce)！
wire [12:0] ra_eff = ce ? ra_addr : ra_hold;
// addrb 用 ra_eff，bank 选择也从 ra_eff 取
```

**★ 第一版我写成了无条件 `ra_hold <= ra_addr`，等于没冻住。**
新加的停顿测试当场抓到（见 26.5）。

### 26.5 补上缺失的那一维激励

`tb_icon_dump.v` 加了 T4：`ce=0` 期间**乱换地址**，`ra_data` 必须一位不变。

```
*** FAIL  T4 停顿冻结：ce=0 时数据变了  addr=3097 got=341f341f exp=18a318a3
```

> **通用规则**
> ① 流水线里**每一个**与相位相关的寄存器都必须挂同一个 `ce`（数据、valid、
>    地址、列号、以及 BRAM 的**地址**）。查的时候用 `grep "always @(posedge clk"`
>    逐个看有没有 `if (ce)`，别只查自己改的那个模块。
> ② **BRAM 的输出寄存器没法用 RTL 的 `ce` 门控** —— 要么冻地址（不加延迟），
>    要么加一级真寄存器并重排流水线。别指望 `oceb`，先确认 `REGMODE`。
> ③ 测试台必须有 **stall 激励**。`pixel_ready` 恒 1 的仿真等于没测流控。
>    最小的检查：停顿期间换输入，输出必须不变。

## 27. `osd_top` 的**新 input 不接** ⇒ 出图纯黑（`osd_pix=Axxx`）

**现象**：`tb_auto_popup` 的 4 张 PPM 全是纯黑（字节统计 `distinct 1`），
而同一套 `osd_top` 在 `tb_osd_icons` 里一切正常。

**根因**：`osd_top` 末级合并是

```verilog
m_pix <= chit_v ? zcol : (txt_pix_s[31:24] != 0) ? txt_pix_s : gfx_pix;
```

`chit_v`（缩放十字条）由 `zoom_on / ax / ay / zoom_sel / zoom_mode` 算出来。
测试台**没接**这几根端口时它们是 `z`（不是 0）⇒ `chit_v = X`
⇒ 三目变成"两边按位合并" ⇒ `m_pix` 的 RGB 全 X、只有两边都相同的 alpha 位还活着
（实测 `osd_pix = c0xxxxxx`：`c0`=192 是面板 alpha，RGB 全 X）。

**为什么难发现**：全 X 落进 PPM 就是 0x00，看起来像"什么都没画"，
而几何/命中/`gfx_pix` 全是对的（探针里 `gfx=c0202020`、`txt=00000000` 都正常）。

**改法**：测试台实例化 `osd_top` 时，**所有 input 端口都要显式给值**
（不用的给 0）。`tb_osd_icons` 早就这么做了，`tb_auto_popup` 漏了 5 根 zoom 端口。

**排查手法**：出图黑的时候先看 `osd_pix` 是不是 `Axxx` 形态

```verilog
$display("probe: osd_pix=%h gfx=%h txt=%h", osd_pix, dut.gfx_pix, dut.txt_pix);
```

- `gfx/txt` 正常而 `osd_pix` 的 RGB 全是 X ⇒ 末级三目的**选择子**是 X ⇒ 去找没接的 input；
- `gfx` 自己就是 X ⇒ 往上游找（例如 `icon_ready=0` 时图标 ROM 的输出寄存器）。

**顺带**：`tb_auto_popup` 例化 `osd_top` 时还写着 `.NSLOT(20)`（[S6]/[LUT-2] 之前的
口径，现在是 8）。`wr_idx` 只写 0..8 ⇒ 9..19 号槽从没被写过（读出 X）。
出图台一律按 `App.v` 的口径给 `NSLOT(8)`，最新的例子见 `tb_infobar_shot.v`。

## 28. "这块区域有没有字"不能用 `alpha > 0` 判 —— 面板本身就盖在字格上

**现象**：给信息条加"关掉自动切换就不显示倒计时"的断言，S2/S3 假 FAIL，
`ink == 512`（整整 32×16 全是"墨"），而屏幕上明明一个字都没有。

**原因**：`osd_pix` 是**合成后**的 OSD 图层。倒计时那两格（x 288..319，y 32..47）
整个被信息条面板覆盖（A=0xC0、RGB=0x202020）⇒ 任何一个像素的 alpha 都 ≥ 8，
"有墨"的判据恒真。ASCII 字形是 1bit 点阵、无抗锯齿，所以逐像素比对本身没问题，
**错的是判据**。

**改法**：按**颜色**判（面板色是已知常量）：

```verilog
if (cap[23:0] != 24'h202020) ink_n = ink_n + 1;   // 字形墨迹 = 非面板色
```

配套护栏（这次一起加的，值得抄）：**同一场景里必须同时断言"该在的还在"** ——
藏进度条的同时查"文件名 ink > 0、分辨率 ink > 0"，否则"把整条信息条关掉"
也能让 S2/S3 全绿。

**另一个副产品**：两个场景如果语义相同（关 / 随音乐），直接比 PPM 的 sha256
比逐像素遍历便宜得多 —— 本次 S2 与 S3 逐位相同，说明"随音乐=关闭"成立。



- **对 integer 型 localparam 做位选**：`PIPE[4:0] + 2` 被 TD 算成 0 ⇒ tick 永不产生。
  写字面量 `5'd6` 并注明来源。
- **复位值必须是常量**：`q_left <= quota_val`（运行时值）会逼 TD 造异步置位，
  复位值写 `0`。
